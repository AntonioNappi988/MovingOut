# Changelog

All notable changes to `movout` are documented in this file.

## [1.0.1] - unreleased

### Added
- **Install mode**: on launch, `movout` now auto-scans common locations (current
  directory, `~`, `~/Downloads`, `~/Desktop`, `/tmp`, plus any `movingout`/`movout`
  subfolder inside them) for `.sh` scripts previously generated by the tool, and
  offers to run one directly on this machine instead of creating a new script.
  - Only scripts generated **for the current distro family** are shown (a script
    built for Arch is never offered on a Debian box, and vice versa).
  - Detection matching (filename hint + `# Generated by MovingOut (movout)` header
    marker) previously skipped any script over 20MB, which silently hid real
    porting scripts that embed sizable custom-script payloads as base64 — that
    size cap has been removed.
  - Both flows (create a new script / install an existing one) now live on the
    same screen, separated by a full-width dashed divider, and an explicit
    "No .sh installation script found for this distro." message is shown when
    none match — the section is never silently hidden.
  - Each found script is listed as `Run on this machine: '<file>' (found in
    <dir>) - Enter to install`, so it's clear upfront what pressing Enter does.
  - Running an existing script now asks for y/N confirmation inside the curses
    UI itself (instead of a plain-terminal prompt after the UI closes); answering
    "no" returns to the picker instead of exiting the tool.
  - A dedicated install animation (spinner + step checklist: reading script,
    installing packages, enabling services, restoring custom scripts, finishing
    up) plays before an existing script runs, visually distinct from the
    box-packing animation shown while generating a new script.
- **Ctrl+F search**: in the package/service/script selection screen, search by
  name and jump straight to the next match instead of scrolling.
- **App header**: every screen now shows `MovingOut v<version>` centered at the
  top, so the running version is always visible.
- **Scanning progress indicator**: picking a target distro can trigger a slow
  scan on machines with large package lists; a centered "Scanning system
  (packages, services, scripts)... / Please wait..." message with an
  indeterminate progress bar now plays while the scan runs in the background,
  so the tool never looks frozen.
- **Post-generation prompt**: after a script is generated, `movout` asks
  "Press 1 to exit, 0 to restart MovingOut", letting you generate another
  script (e.g. for a different target distro) without relaunching the command.

### Added
- **Online package-name validation**: when porting to a different distro
  family, `movout` now checks each translated package name against
  [Repology](https://repology.org) before generating the script (with a
  live fallback to the official Arch and Fedora/RHEL package-search APIs
  when Repology has no data), instead of trusting the static translation
  table blindly.
  - Runs in the background with the same progress-bar animation used for
    scanning, so it never looks frozen; results are cached on disk for 30
    days to avoid re-querying the same package repeatedly.
  - Names confirmed **not to exist** for the target distro are flagged with
    a comment right above the install line in the generated script, and
    their failure-log entry explicitly says the name is likely wrong.
  - Every network failure (offline, rate-limited, unsupported family)
    degrades to "unverified" and never blocks script generation; after a
    couple of consecutive connection failures it stops hitting the network
    for the rest of the batch instead of hanging.
  - Skipped entirely for same-distro reinstalls, where the package is
    already known-good on this exact machine.
- **Explicit end-of-script failure summary**: the generated script used to
  just point at `movingout-failed.log`; it now also prints every failed
  package/service by name directly to the terminal when it finishes
  running, so the person on the new machine sees immediately what needs
  manual attention instead of having to go open a log file.

### Changed
- Bumped version from `1.0.0` to `1.0.1`.
- **One-liner install**: `install.sh` now works when piped directly (`curl -fsSL
  .../install.sh | bash`), auto-fetching the source itself (via `git clone`, or
  a `curl | tar` fallback) when it isn't run from a local clone. No more
  clone-then-run-script dance.

### Fixed
- **AUR package (`packaging/PKGBUILD`) was broken**: `makepkg` failed every
  time because the script `cd`'d into `movingout-$pkgver` (lowercase), but the
  GitHub tarball actually extracts to `MovingOut-$pkgver` (the repo's real
  casing). Fixed and verified with a clean `makepkg` build.
- **Alpine mapping never applied**: `mapping.py` keyed its Alpine
  translations under `"apk"`, but every caller (`distro.py`, the target-distro
  picker, the generator) uses the family name `"alpine"` — so `translate()`
  always fell through to the unchanged Debian name on Alpine, silently
  defeating the mapping table for that whole family. Fixed by renaming the
  keys to `"alpine"`.

## [1.0.0]

- Initial release: curses TUI to scan manually installed packages, enabled
  systemd services and custom user scripts, and generate a single portable
  `.sh` installer to reproduce them on another machine (same distro or a
  different one), with cross-distro package-name translation and risk
  flagging for system-critical items.
